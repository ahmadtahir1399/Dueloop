Getting your keys

Easy steps for every setting the app needs, using hosted services with a free plan where one exists.

What is a "key"? A key is a long piece of text. It lets our app talk to another service, such as the database or the email service. You copy it from that service's website and paste it into the app's settings.

Where do the keys go?

  • Environment variables (env). Most keys go here. Your hosting service has a page called something like "Environment variables". You can also put them in a file named .env on your server. The file .env.example in this project lists every name.
  • The app's own Settings page. Some passwords (email, WhatsApp, Stripe) are NOT env keys. You type them into Settings → Integrations after you log in. The app keeps them locked in the database vault.

Five safety rules

  1. A secret key is like a house key. Never post it in chat, email, a screenshot or a public file.
  2. Never put a secret key in a variable whose name starts with NEXT_PUBLIC_. Those go to every visitor's browser.
  3. Never put a .env file into git.
  4. If a secret key leaks, make a new one at the service and delete the old one. Deleting the text is not enough.
  5. Copy a new key at once. Many services show it only one time.

Part 1: Supabase, the database required free plan

Supabase holds all the app's data. Its Free plan costs $0. Supabase's pricing page says it includes a 500 MB database, 1 GB file storage and up to 2 active projects, and that free projects are paused after 1 week of inactivity.

Step A: make a project

  1. Go to supabase.com and sign up.
  2. Click New project. Give it a name.
  3. Type a strong database password. Save it now in a password manager. You need it in Step D.
  4. Pick the region closest to your customers. Click create and wait a few minutes.

Step B: the project address

Click the Connect button at the top of your project. Copy the Project URL. It looks like https://abcdefgh.supabase.co. Put the same value in two keys:

NEXT_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
SUPABASE_URL=https://abcdefgh.supabase.co

Step C: the two API keys

  1. Open Settings → API Keys.
  2. Copy the publishable key (starts with sb_publishable_). It is safe in a browser.
  3. Copy a secret key (starts with sb_secret_). It is secret: it can read every row.
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
SUPABASE_SERVICE_ROLE_KEY=sb_secret_...
TipThe older keys (anon and service_role) are on the same page. The app also accepts the service_role key in SUPABASE_SERVICE_ROLE_KEY.

Step D: the database connection string

  1. Click Connect again.
  2. Choose the Session pooler string. It works on every network (Supabase says the direct connection needs IPv6 on the Free plan, and the session pooler works over IPv4 on every plan).
  3. Copy it. Replace [YOUR-PASSWORD] with your database password from Step A. If the password has symbols like & # ? or spaces, they must be percent-encoded (or pick a password of only letters and numbers).

Use the same string for both keys. Both are secret:

SUPABASE_DB_URL=postgresql://postgres.abcdefgh:PASS@POOLER-HOST:5432/postgres
WORKER_DATABASE_URL=postgresql://postgres.abcdefgh:PASS@POOLER-HOST:5432/postgres

Here PASS stands for your database password. Copy the real pooler host from the Connect window. You cannot guess it from the region.

Before the first startThe database needs the pgmq and pg_cron extensions turned on before the app's tables are created. See docs/self-hosting.md ("Hosted Supabase checklist"). This was not tested on a hosted project yet.

Part 2: your app's web address required

These are not keys from a service. They are the https address where people open your app. Your hosting service shows it after you deploy (for example https://app.yourbusiness.example).

PUBLIC_APP_URL=https://app.yourbusiness.example
NEXT_PUBLIC_APP_URL=https://app.yourbusiness.example
  • PUBLIC_APP_URL: used in pay links and opt-out links in every reminder. It must start with https://.
  • WEBHOOKS_PUBLIC_URL: only if your webhooks service has a different address. Otherwise leave it empty.
  • TRUST_PROXY_HOPS: how many proxies (load balancers) sit in front of the app. If you do not know, leave it at 0.
Hosting is not covered hereThe app runs four programs all the time (web, worker, reply processor, webhooks). Free hosting plans often sleep or stop long-running programs, so check your host's plan. docs/self-hosting.md explains the containers.

Part 3: email sending free plan

The app sends reminders by email through an SMTP service. Pick one option. Option A is better for a real business. Option B is fine for testing with your own Gmail.

Option A: Brevo

Brevo's own page says its free plan can send 300 emails per day.

  1. Go to brevo.com and sign up for the free plan.
  2. Add and verify the email address or domain you will send from (Brevo shows you how). Use your own business domain if you can.
  3. Open SMTP & API settings, then the SMTP tab.
  4. Click to generate a new SMTP key. Brevo says: use an SMTP key, not an API key. Copy it now.
  5. On the same tab, copy the SMTP server name and your login.
SMTP_HOST=(the SMTP server shown on Brevo's SMTP tab)
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=(the login shown on Brevo's SMTP tab)

Option B: Gmail

  1. Turn on 2-Step Verification on your Google account.
  2. Go to myaccount.google.com/apppasswords. Make a new app password. Copy it.
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=(your full Gmail address)
Gmail limitsGoogle says app passwords are "not recommended", and they may not exist for work, school or Advanced Protection accounts. Changing your Google password cancels them. Use Gmail only for testing.

Then, in the app

  1. Log in as an owner. Open Settings → Integrations.
  2. Under Set channel credentials, choose email (SMTP password).
  3. Paste the Brevo SMTP key (or the Gmail app password). Click Save secret.
One step with no screen yet: the sender address The app has no form for the "From" address. Your operator sets it once, in Supabase: SQL Editor, change the values, then Run. Find the tenant id in Table Editor → tenants. (This SQL was checked against the table definition but not run in this session.) 
insert into public.channel_accounts (tenant_id, channel, config)
values ('TENANT-ID', 'email',
        '{"from_address": "billing@yourbusiness.example", "from_name": "Your Business"}')
on conflict (tenant_id, channel)
do update set config = public.channel_accounts.config || excluded.config;
The from address must be one your email service has verified.

Part 4: OpenAI, to read customer replies paid optional

When a customer answers a reminder ("I will pay on the 15th"), the AI can suggest what the reply means. A person or the app's rules still decide. The AI never closes an invoice or sends a message.

Free choice: skip this partIf you leave CLASSIFIER empty, every reply goes to a person as a task. Nothing is lost. This costs nothing.
CostWe found no official OpenAI free plan for the API. Expect to add a payment method and buy credit first. Check OpenAI's billing page for the current rules.

Steps

  1. Go to platform.openai.com and sign up. OpenAI may ask to verify your phone.
  2. Open Billing and add credit.
  3. Open API keys. Click Create new secret key. Give it a name, pick your project, and create it.
  4. Copy the key at once (it usually starts with sk-proj-). It is shown only one time.
  5. Choose a model on OpenAI's Models page. It must support "Structured Outputs". OpenAI's docs (read 29 October 2026) say to start new projects with gpt-6-astra.
CLASSIFIER=openai
CLASSIFIER_MODEL=gpt-6-astra
OPENAI_API_KEY=sk-proj-...

Also read payment screenshots? (optional)

The app can ask the AI for hints from a payment screenshot a customer sends. The hints are only shown to a person; they never mark money as paid. Each business must also switch this on in its own settings.

PROOF_EXTRACTION=openai
PROOF_EXTRACTION_MODEL=(an OpenAI model that can read images)
Already have Claude?Use CLASSIFIER=anthropic and ANTHROPIC_API_KEY instead. Use one provider, not both.

Not tested with a real OpenAI key yet (tested with recorded answers only).

Part 5: WhatsApp test number optional

WhatsApp uses Meta's WhatsApp Cloud API. Meta gives you a test phone number to start. Real sending needs business verification and approved message templates, which take time.

Step A: app and token

  1. Register at developers.facebook.com.
  2. In the App Dashboard, click Create App. Choose the use case Connect with customers through WhatsApp. Pick your business portfolio.
  3. Click Start using the API. Note the test number's Phone number ID.
  4. Make a permanent token: in Business Settings → System users, add a system user, give it your app and WhatsApp account, then Generate token with the permissions business_management, whatsapp_business_messaging and whatsapp_business_management. (Meta says the temporary token expires quickly.)
  5. In the app: Settings → Integrations → Set channel credentials → whatsapp (access token). Paste the token.

Step B: env keys

  • WHATSAPP_GRAPH_VERSION: the Graph API version. Meta's changelog lists v26.0 as the newest (29 July 2026).
  • WHATSAPP_APP_SECRET secret: in the App Dashboard, open App settings → Basic and copy the App secret.
  • WHATSAPP_VERIFY_TOKEN secret: you make this up. Any long random text. You type the same text into Meta in Step C.
WHATSAPP_GRAPH_VERSION=v26.0
WHATSAPP_APP_SECRET=...
WHATSAPP_VERIFY_TOKEN=make-up-a-long-random-text

Step C: tell Meta where to send replies

  1. In the App Dashboard open WhatsApp → Configuration (for this app type it may be under Use cases → Customize → Configuration).
  2. Callback URL: https://YOUR-WEBHOOKS-ADDRESS/webhooks/whatsapp
  3. Verify token: the same text as WHATSAPP_VERIFY_TOKEN.
  4. Subscribe to the messages field.
One step with no screen yet: the phone number IDYour operator runs this once in Supabase's SQL Editor (checked against the table definition, not run in this session): 
insert into public.channel_accounts (tenant_id, channel, config, external_account_id)
values ('TENANT-ID', 'whatsapp', '{"phone_number_id": "PHONE-NUMBER-ID"}', 'PHONE-NUMBER-ID')
on conflict (tenant_id, channel)
do update set config = public.channel_accounts.config || excluded.config,
              external_account_id = excluded.external_account_id;

Part 6: Stripe pay links sandbox optional

Stripe lets customers pay by card from a link in the reminder. A Stripe sandbox is a test area: no real money moves. Each business connects its own Stripe account inside the app.

Step A: one env key

PAYMENTS_WEBHOOKS=true

Step B: the API key

  1. Sign up at stripe.com. Make or pick a sandbox.
  2. Open the API keys page (dashboard.stripe.com/apikeys).
  3. Stripe recommends a restricted key (starts with rk_test_) over the secret key (sk_test_). The app makes payment links and reads checkout sessions. Which exact restricted permissions are enough was not tested.

Step C: the webhook and its signing secret

Stripe needs the app's webhook address. The app shows that address only after you connect, and to connect it asks for Stripe's signing secret. So do it in this order:

  1. In Stripe, open Workbench → Webhooks and click Create an event destination.
  2. Choose Your account and the Snapshot payload. API version: 2026-09-30.endive (the version this app uses).
  3. Select these events: checkout.session.completed, checkout.session.async_payment_succeeded, checkout.session.async_payment_failed, charge.refunded, charge.dispute.created.
  4. Choose Webhook endpoint. For now, enter https://YOUR-WEBHOOKS-ADDRESS/webhooks/payments/pending.
  5. Click Reveal secret. Copy the signing secret (starts with whsec_).
  6. In the app: Settings → Integrations → Connect a payment account. Provider Stripe, mode test, paste the API key and the whsec_ secret. Click Connect.
  7. The app shows the real webhook URL once. Copy it. In Stripe, edit the endpoint and paste this URL.
Check after step 7Make sure the signing secret in Stripe did not change when you edited the URL. This order was not tested with a real Stripe account.

Part 7: alerts and the rest optional

  • OPS_ALERT_EMAIL: your email. The watchdog emails problems here (it uses the SMTP settings from Part 3).
  • OPS_ALERT_FROM: the "From" address for those alerts (a verified sender).
  • Slack alerts: make a Slack incoming webhook URL, then paste it in Settings → Integrations → slack (webhook URL). It is not an env key.
  • NODE_ENV: production.

Never set these on a real server

  • PAYMENTS_ALLOW_FAKE: a fake payment provider, for tests and the demo only.
  • DEMO_MODE, DEMO_NOW, NOW_ISO and the other DEMO_* keys.
  • NEXT_RUNTIME (Next.js sets it itself).
  • Test-only keys: *_SMOKE, STRIPE_TEST_API_KEY, WHATSAPP_TOKEN, EVAL_LIVE, PROOF_EVAL*, SEND_LOG, APPLY_LOG, MAILPIT_URL.

After you fill them in, run pnpm doctor --service web (and again with worker, processor, webhooks) on the server. It checks that the needed keys are set, then tries to reach the database, Supabase and the SMTP port. It never prints a key's value.
