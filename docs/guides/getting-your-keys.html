Getting your keys

Easy steps for every setting the app needs, using hosted services with a free plan where one exists.

What is a "key"? A key is a long piece of text. It lets our app talk to another service, such as the database or the email service. You copy it from that service's website and paste it into the right place.

Where do the keys go?

  • Server settings (env). Most keys go here. Your hosting service has a page called something like "Environment variables". You can also put them in a file named .env on your server. The file .env.example in this project lists every name.
  • The app's own Settings. Some things are typed into the app after you log in as the owner: Settings → Integrations (email password, sender address, WhatsApp, Stripe, Slack) and each customer's page (consent). The app keeps passwords locked in the database vault and never shows them again.

Five safety rules

  1. A secret key is like a house key. Never post it in chat, email, a screenshot or a public file.
  2. Never put a secret key in a name that starts with NEXT_PUBLIC_. Those go to every visitor's browser.
  3. Never put a .env file into git.
  4. If a secret key leaks, make a new one at the service and delete the old one. Deleting the text is not enough.
  5. Copy a new key at once. Many services show it only one time.

Part 1: Supabase, the database required free plan

Supabase holds all the app's data. Its Free plan costs $0. It includes a 500 MB database, 1 GB of file storage and up to 2 active projects. Free projects are paused after 1 week with no activity. (provider: supabase.com/pricing)

Step A: make a project

  1. Go to supabase.com and sign up.
  2. Click New project. Give it a name.
  3. Type a database password that uses only letters and numbers. Save it now in a password manager. You need it in Step D.
  4. Pick the region closest to your customers. Click create and wait a few minutes.

Step B: the project address

Click the Connect button at the top of your project. Copy the Project URL. It looks like https://abcdefgh.supabase.co. Put the same value in two keys:

NEXT_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
SUPABASE_URL=https://abcdefgh.supabase.co

Step C: the two API keys

  1. Open Settings → API Keys.
  2. Copy the publishable key (starts with sb_publishable_). It is safe in a browser.
  3. Copy a secret key (starts with sb_secret_). It is secret: it can read every row.
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
SUPABASE_SERVICE_ROLE_KEY=sb_secret_...
TipThe older service_role key on the same page also works in SUPABASE_SERVICE_ROLE_KEY.

Step D: the database connection string

  1. Click Connect again.
  2. Choose Session pooler. It works on any internet connection.
  3. Copy it. Replace [YOUR-PASSWORD] with your database password from Step A.

Use the same string for both keys. Both are secret:

SUPABASE_DB_URL=postgresql://postgres.abcdefgh:PASS@POOLER-HOST:5432/postgres
WORKER_DATABASE_URL=postgresql://postgres.abcdefgh:PASS@POOLER-HOST:5432/postgres

Here PASS stands for your database password. Copy the real pooler host from the Connect window. You cannot guess it from the region.

Step E: tell Supabase your app's address

Open Authentication → URL Configuration. Set Site URL to your app address from Part 2. Without this, sign-up and login emails point to the wrong place. (Not yet tried on a hosted project.)

Before the first startThe database needs the pgmq and pg_cron extensions turned on before the app's tables are created. See docs/self-hosting.md ("Hosted Supabase checklist"). Not yet tried on a hosted project.

Part 2: your app's web address required

These are not keys from a service. They are the https address where people open your app. Your hosting service shows it after you deploy (for example https://app.yourbusiness.example).

  • PUBLIC_APP_URL required: used in pay links and opt-out links in every reminder. It must start with https://.
  • NEXT_PUBLIC_APP_URL (optional): only a backup address for sign-up emails. Use the same value.
  • WEBHOOKS_PUBLIC_URL: the https address of the webhooks program (Part 5 and 6 send messages there). Leave it empty only if your proxy sends /webhooks/ on your app address to that program.
  • TRUST_PROXY_HOPS: leave at 0 unless your host tells you a number.
PUBLIC_APP_URL=https://app.yourbusiness.example
NEXT_PUBLIC_APP_URL=https://app.yourbusiness.example
WEBHOOKS_PUBLIC_URL=https://hooks.yourbusiness.example
Hosting is not covered hereThe app has four programs: web, worker, reply processor and webhooks. The first three run all the time. Free hosting plans often sleep or stop long-running programs, so check your host's plan. If you use neither WhatsApp nor Stripe, do not run the webhooks program (it refuses to start with nothing to receive). docs/self-hosting.md explains the containers.

Part 3: email sending free plan

The app sends reminders by email through an SMTP service. Pick one option. Option A is better for a real business. Option B is fine for testing with your own Gmail.

Option A: Brevo

The free plan can send 300 emails per day. (provider: brevo.com)

  1. Go to brevo.com and sign up for the free plan.
  2. Add and verify the email address or domain you will send from (Brevo shows you how). Use your own business domain if you can.
  3. Open SMTP & API settings, then the SMTP tab.
  4. Click to generate a new SMTP key. Use an SMTP key, not an API key. Copy it now.
  5. On the same tab, copy the SMTP server name and your login.
SMTP_HOST=(the SMTP server shown on Brevo's SMTP tab)
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=(the login shown on Brevo's SMTP tab)
SMTP_PASSWORD=(the SMTP key)          # secret

Option B: Gmail

  1. Turn on 2-Step Verification on your Google account.
  2. Go to myaccount.google.com/apppasswords. Make a new app password. Copy it.
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=(your full Gmail address)
SMTP_PASSWORD=(the app password)      # secret
Gmail limitsGoogle says app passwords are not recommended, and they may not exist for work, school or Advanced Protection accounts. Changing your Google password cancels them. Use Gmail only for testing.

Then, in the app (owner)

  1. Open Settings → Integrations.
  2. In the Email sender form, type the Sender email address (one your email service has verified) and, if you like, a Sender name. Click Save sender.
  3. Only if this business uses its own SMTP password instead of SMTP_PASSWORD: in the Channels box, choose email (SMTP password) under Channel, paste it into Secret and click Save secret. A password saved here wins over SMTP_PASSWORD.
Templates are readyA new business gets standard English email reminders (friendly, nudge, firm, receipt). Read them in Settings → Templates and change the words if you like. If one is missing, that page shows an Add the standard email templates button.

Part 4: OpenAI, to read customer replies paid optional

When a customer answers a reminder ("I will pay on the 15th"), the AI can suggest what the reply means. A person or the app's rules still decide. The AI never closes an invoice or sends a message.

Free choice: skip this partIf you leave CLASSIFIER empty, every reply goes to a person as a task. Nothing is lost. This costs nothing.
CostWe found no official OpenAI free plan for the API. Expect to add a payment method and buy credit first. Check OpenAI's billing page for the current rules.

Steps

  1. Go to platform.openai.com and sign up. OpenAI may ask to check your phone number.
  2. Open Billing and add credit.
  3. Open API keys. Click Create new secret key. Give it a name, pick your project, and create it.
  4. Copy the key at once (new keys usually start with sk-proj- (provider)). It is shown only one time.
  5. Choose a model on OpenAI's Models page. It must support "Structured Outputs". OpenAI's docs say to start new projects with gpt-6-astra. (provider, 29 Oct 2026)
CLASSIFIER=openai
CLASSIFIER_MODEL=gpt-6-astra
OPENAI_API_KEY=sk-proj-...            # secret

If the model is a "reasoning" model, also set CLASSIFIER_REASONING_EFFORT=low. Otherwise leave it empty.

Also read payment screenshots? (optional)

The app can ask the AI for hints from a payment screenshot a customer sends. The hints are only shown to a person; they never mark money as paid.

PROOF_EXTRACTION=openai
PROOF_EXTRACTION_MODEL=(an OpenAI model that can read images)

Each business must also tick Let AI read payment proofs in Settings.

Already have Claude?Use anthropic instead of openai and set ANTHROPIC_API_KEY. Pick one provider for CLASSIFIER. Proof hints may use the same or the other one.

Not yet tried with a real OpenAI key (tested with recorded answers only).

Part 5: WhatsApp test number optional

WhatsApp uses Meta's WhatsApp Cloud API. Meta gives you a test phone number to start. To message real customers, Meta must check your business and approve your message texts. This takes days.

Step A: app and token

  1. Register at developers.facebook.com.
  2. In the App Dashboard, click Create App. Choose Connect with customers through WhatsApp. Pick your business portfolio.
  3. Click Start using the API. Note the test number's Phone number ID (digits only).
  4. Make a permanent token: in Business Settings → System users, add a system user, give it your app and WhatsApp account, then Generate token with the permissions business_management, whatsapp_business_messaging and whatsapp_business_management. The first token Meta shows expires quickly.

Step B: server keys

  • WHATSAPP_GRAPH_VERSION: the Graph API version, for example v26.0 (newest on 29 July 2026). (provider)
  • WHATSAPP_APP_SECRET secret: in the App Dashboard, open App settings → Basic and copy the App secret.
  • WHATSAPP_VERIFY_TOKEN secret: you make this up. Any long random text. You type the same text into Meta in Step C.
WHATSAPP_GRAPH_VERSION=v26.0
WHATSAPP_APP_SECRET=...
WHATSAPP_VERIFY_TOKEN=make-up-a-long-random-text

Step C: tell Meta where to send replies

  1. In the App Dashboard open WhatsApp → Configuration (for this app type it may be under Use cases → Customize → Configuration).
  2. Callback URL: https://YOUR-WEBHOOKS-ADDRESS/webhooks/whatsapp
  3. Verify token: the same text as WHATSAPP_VERIFY_TOKEN.
  4. Subscribe to the messages field.

Step D: in the app

  1. Settings → Integrations, form WhatsApp number: paste the Phone number ID, click Save WhatsApp number.
  2. Same page, Channels box: choose whatsapp (access token) under Channel, paste the permanent token into Secret, click Save secret.
  3. Settings: set the Monthly budget for WhatsApp and SMS above 0. At 0, WhatsApp is blocked.
  4. For each customer who agreed to WhatsApp messages: open the customer, use Record consent, choose WhatsApp and write how they agreed. Customers without it get no WhatsApp reminders.
  5. In Settings → Templates, use New WhatsApp template: type the exact text Meta approved, its Name at Meta and Language code at Meta. It starts as pending. An owner then clicks Meta approved this text; only then is it sent.
  6. In Settings → Policies, add a WhatsApp step that uses that template key.

Part 6: Stripe pay links sandbox optional

Stripe lets customers pay by card from a link in the reminder. A Stripe sandbox is a test area: no real money moves. Each business connects its own Stripe account inside the app.

Step A: one server key

PAYMENTS_WEBHOOKS=true

Step B: the API key

  1. Sign up at stripe.com. Make or pick a sandbox.
  2. Open the API keys page (dashboard.stripe.com/apikeys).
  3. Stripe suggests a limited key (starts with rk_test_) instead of the secret key (sk_test_). The app needs it to make, read and turn off payment links. Which exact permissions are enough was not tested.

Step C: connect, then add the signing secret

  1. In the app: Settings → Integrations, form Connect a payment account. Provider Stripe, mode test, paste the API key. Leave Webhook signing secret empty for now. Click Connect.
  2. The app shows the webhook URL once. Copy it. The account stays switched off for now, so no pay link is made yet.
  3. In Stripe, open Workbench → Webhooks and click Create an event destination. Choose Your account and the Snapshot payload. API version: 2026-09-30.endive (the version this app uses).
  4. Select these events: checkout.session.completed, checkout.session.async_payment_succeeded, checkout.session.async_payment_failed, charge.refunded, charge.dispute.created.
  5. Choose Webhook endpoint and paste the webhook URL from step 2.
  6. Click Reveal secret and copy the signing secret (starts with whsec_).
  7. Back in the app, form Webhook signing secret: choose the Stripe account, paste it, click Save signing secret. The account is now switched on.

The key must match the mode: a test account needs a test key. Not yet tried with a real Stripe account.

Part 7: alerts, checks and your final list

Alerts (optional)

  • OPS_ALERT_EMAIL and OPS_ALERT_FROM: where the operator watchdog emails system problems, and the sender it uses (a verified sender). It logs in with SMTP_USER and SMTP_PASSWORD.
  • Slack (per business): make a Slack incoming webhook URL (it starts with https://hooks.slack.com/), then in Settings → Integrations choose slack (webhook URL) under Channel and paste it into Secret. That business's alerts then go to Slack; without it they go by email to its owners.

Never set these on a real server

  • PAYMENTS_ALLOW_FAKE: a fake payment provider, for tests and the demo only.
  • DEMO_MODE, DEMO_NOW, NOW_ISO and the other DEMO_* keys.
  • NEXT_RUNTIME and OPENAI_LOG.
  • Test-only keys: *_SMOKE, STRIPE_TEST_API_KEY, WHATSAPP_TOKEN, EVAL_LIVE, PROOF_EVAL*, SEND_LOG, APPLY_LOG, MAILPIT_URL.

Check your setup

On the server run pnpm doctor --service web, then again with worker, processor and webhooks. It checks that the needed keys are set and well formed, reaches the database (WORKER_DATABASE_URL), checks the database version, reaches Supabase, and opens the SMTP port. It does not test your SMTP password. It never prints a key's value.
