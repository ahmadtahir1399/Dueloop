Getting your keys

Easy steps for every setting the app needs, using hosted services with a free plan where one exists.

What is a "key"? A key is a long piece of text. It lets our app talk to another service, such as the database or the email service. You copy it from that service's website and paste it into the right place.

Where do the keys go?

  • Server settings (env). Most keys go here. Your hosting service has a page called something like "Environment variables". You can also put them in a file named .env on your server. The file .env.example in this project lists every name.
  • Inside the app. Some settings go inside the app. Log in as the owner. Open Settings → Integrations for email, WhatsApp, Stripe and Slack. Open each customer's page to record consent. Passwords you type there are locked in the database vault and never shown again.

Five safety rules

  1. A secret key is like a house key. Never post it in chat, email, a screenshot or a public file.
  2. Never put a secret key in a name that starts with NEXT_PUBLIC_. Those go to every visitor's browser.
  3. Never put a .env file into git.
  4. If a secret key leaks, make a new one at the service and delete the old one. Deleting the text is not enough.
  5. Copy a new key at once. Many services show it only one time (their own words).

Part 1: Supabase, the database required free plan

Supabase holds all the app's data. Its Free plan costs $0. It includes a 500 MB database, 1 GB of file storage and up to 2 active projects. Free projects are paused after 1 week with no activity. (provider: supabase.com/pricing)

Step A: make a project

  1. Go to supabase.com and sign up.
  2. Click New project. Give it a name.
  3. Type a database password that uses only letters and numbers. Save it now in a password manager. You need it in Step D.
  4. Pick the region closest to your customers. Click create and wait a few minutes.

Step B: the project address

Click the Connect button at the top of your project. Copy the Project URL. It looks like https://abcdefgh.supabase.co. Put the same value in two keys:

NEXT_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
SUPABASE_URL=https://abcdefgh.supabase.co

Step C: the two API keys

  1. Open Settings → API Keys.
  2. Copy the publishable key (starts with sb_publishable_). It is safe in a browser.
  3. Copy a secret key (starts with sb_secret_). It is secret: it can read every row.
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
SUPABASE_SERVICE_ROLE_KEY=sb_secret_...
TipThe older service_role key on the same page also works in SUPABASE_SERVICE_ROLE_KEY.

Step D: the database connection string

  1. Click Connect again.
  2. Choose Session pooler.
  3. Copy it. Replace [YOUR-PASSWORD] with your database password from Step A.

Use the same string for both keys. Both are secret:

SUPABASE_DB_URL=postgresql://postgres.abcdefgh:PASS@POOLER-HOST:5432/postgres
WORKER_DATABASE_URL=postgresql://postgres.abcdefgh:PASS@POOLER-HOST:5432/postgres

Here PASS stands for your database password. Copy the real pooler host from the Connect window. You cannot guess it from the region.

Step E: tell Supabase your app's address

Open Authentication → URL Configuration. Set Site URL to your app address from Part 2. Without this, sign-up and login emails point to the wrong place. (Not yet tried on a hosted project.)

Before the first startTwo database add-ons must be switched on first (see docs/self-hosting.md, "Hosted Supabase checklist"). Not yet tried on a hosted project.

Part 2: your app's web address required

These are not keys from a service. They are the https address where people open your app. Your hosting service shows it after you deploy (for example https://app.yourbusiness.example).

  • PUBLIC_APP_URL required: used in pay links and opt-out links in every reminder. Use an https:// address.
  • NEXT_PUBLIC_APP_URL (optional): only a backup address for sign-up emails. Use the same value.
  • WEBHOOKS_PUBLIC_URL: the https address of the webhooks program (WhatsApp and Stripe send messages there). If you leave it empty, the app uses your app address. Then ask your host to send /webhooks/ pages to the webhooks program.
  • TRUST_PROXY_HOPS: most hosts put a "proxy" in front of your app. Ask your host how many. Type that number. If there is none, type 0.
PUBLIC_APP_URL=https://app.yourbusiness.example
NEXT_PUBLIC_APP_URL=https://app.yourbusiness.example
WEBHOOKS_PUBLIC_URL=https://hooks.yourbusiness.example
TRUST_PROXY_HOPS=0
Hosting is not covered hereThe app has four programs: web, worker, reply processor and webhooks. Each one you use must run all the time. Free hosting plans often sleep or stop long-running programs, so check your host's plan. If you use neither WhatsApp nor Stripe, do not run the webhooks program (it refuses to start with nothing to receive). docs/self-hosting.md explains the containers.

Part 3: email sending free plan

The app sends reminders by email through an SMTP service (the usual way programs send email). Pick one option. Option A is better for a real business. Option B is fine for testing with your own Gmail.

Option A: Brevo

The free plan can send 300 emails per day. (provider: brevo.com)

  1. Go to brevo.com and sign up for the free plan.
  2. Add and verify the email address or domain you will send from (Brevo shows you how). Use your own business domain if you can.
  3. Open SMTP & API settings, then the SMTP tab.
  4. Click to generate a new SMTP key. Use an SMTP key, not an API key. Copy it now.
  5. On the same tab, copy the SMTP server name and your login.
SMTP_HOST=(the SMTP server shown on Brevo's SMTP tab)
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=(the login shown on Brevo's SMTP tab)
SMTP_PASSWORD=(the SMTP key)          # secret

Option B: Gmail

  1. Turn on 2-Step Verification on your Google account.
  2. Go to myaccount.google.com/apppasswords. Make a new app password. Copy it.
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=(your full Gmail address)
SMTP_PASSWORD=(the app password)      # secret
Gmail limitsGoogle says app passwords are not recommended, and they may not exist for work, school or Advanced Protection accounts. Changing your Google password cancels them. (provider) Use Gmail only for testing.

The app always protects your email password. If the mail server cannot do that on port 587, sending stops.

Several businesses on one server?

Set SMTP_FROM_DOMAINS to the sender domains your mail service has verified, for example SMTP_FROM_DOMAINS=yourbusiness.example. Then the server only sends from these domains.

Then, in the app (owner)

  1. Open Settings → Integrations.
  2. In the Channels box, fill in Sender email address (one your email service has verified) and, if you like, the sender name. Click Save sender.
Templates are readyA new business gets standard English email reminders (friendly, nudge, firm, receipt). Read them in Settings → Templates and change the words if you like. If one is missing, that page shows an Add the standard email templates button.
Email replies are not read by the app yetWhen a customer answers a reminder email, the answer goes to your own inbox. Read it there and act on it yourself. Reminder emails have a stop link at the bottom. Receipts ask the customer to reply instead, so watch your inbox for "stop" replies. WhatsApp replies are read by the app.

Your own mail server instead of the server's: only if the operator sets SMTP_ALLOW_TENANT_HOST=true. Then the same box asks for your Mail server, Port and Login. The password goes in Secret, with Channel set to "email (password for your own mail server)", then Save secret.

By default every reminder waits for a person to approve it: open Approvals to send them. You can change this in Settings.

Part 4: OpenAI, to read WhatsApp replies paid optional

When a customer answers on WhatsApp ("I will pay on the 15th"), the AI can suggest what the reply means. A person or the app's rules still decide. The AI never closes an invoice or sends a message.

Free choice: skip this partIf you leave CLASSIFIER empty, every reply goes to a person as a task. This costs nothing.
CostWe found no official OpenAI free plan for the API. Expect to add a payment method and buy credit first. Check OpenAI's billing page for the current rules.

Steps

  1. Go to platform.openai.com and sign up. OpenAI may ask to check your phone number. (provider)
  2. Open Billing and add credit.
  3. Open API keys. Click Create new secret key. Give it a name, pick your project, and create it.
  4. Copy the key at once (new keys usually start with sk-proj- (provider)). It is shown only one time.
  5. Pick a model that OpenAI says supports "Structured Outputs" (fixed-format answers). OpenAI's docs say to start new projects with gpt-6-astra. (provider, 29 Oct 2026)
CLASSIFIER=openai
CLASSIFIER_MODEL=gpt-6-astra
OPENAI_API_KEY=sk-proj-...            # secret

If OpenAI calls your model a "reasoning" model, also set CLASSIFIER_REASONING_EFFORT=low. Otherwise leave it out.

Also read payment screenshots? (optional)

The app can ask the AI for hints from a payment screenshot a customer sends. The hints are only shown to a person; they never mark money as paid.

PROOF_EXTRACTION=openai
PROOF_EXTRACTION_MODEL=(an OpenAI model that reads images AND supports Structured Outputs)

Each business must also tick Let AI read payment proofs in Settings.

Already have Claude?Use anthropic instead of openai and set ANTHROPIC_API_KEY. Pick one provider for CLASSIFIER. Proof hints may use the same or the other one.

Not yet tried with a real OpenAI key (tested with recorded answers only).

Part 5: WhatsApp test number optional

WhatsApp uses Meta's WhatsApp Cloud API. Meta gives you a test phone number to start. To message real customers, Meta must check your business and approve your message texts. (provider)

Step A: app and token

  1. Register at developers.facebook.com.
  2. In the App Dashboard, click Create App. Choose Connect with customers through WhatsApp. Pick your business portfolio.
  3. Click Start using the API. Note the test number's Phone number ID (digits only).
  4. Make a token that does not expire. Open Business Settings → System users. Add a system user. Give it your app and your WhatsApp account. Click Generate token. Tick business_management, whatsapp_business_messaging and whatsapp_business_management. (Meta says the first token it shows expires quickly. (provider))

Step B: server keys

  • WHATSAPP_GRAPH_VERSION: the Graph API version, for example v26.0 (released 29 July 2026 (provider)). Without it, WhatsApp is switched off.
  • WHATSAPP_APP_SECRET secret: in the App Dashboard, open App settings → Basic and copy the App secret.
  • WHATSAPP_VERIFY_TOKEN secret: you make this up. Any long random text. You type the same text into Meta in Step C.
WHATSAPP_GRAPH_VERSION=v26.0
WHATSAPP_APP_SECRET=...
WHATSAPP_VERIFY_TOKEN=make-up-a-long-random-text

Not here: WHATSAPP_PHONE_NUMBER_ID and WHATSAPP_TOKEN are for a test script only. The Phone number ID goes in Settings (Step D).

Step C: tell Meta where to send replies

  1. In the App Dashboard open WhatsApp → Configuration (for this app type it may be under Use cases → Customize → Configuration).
  2. Callback URL: https://YOUR-WEBHOOKS-ADDRESS/webhooks/whatsapp
  3. Verify token: the same text as WHATSAPP_VERIFY_TOKEN.
  4. Subscribe to the messages field.

Step D: in the app (in this order)

  1. Settings → Integrations, Channels box: choose whatsapp (access token) under Channel, paste the token into Secret, click Save secret.
  2. Same box: type the Phone number ID (from Meta, digits only) and click Save WhatsApp number. The app asks Meta, with your token, that this number is yours. You should see "Saved. Meta confirmed this number." If it says "Saved for sending…", save the token first, check that WHATSAPP_GRAPH_VERSION (with the "v") is set on the web server too, and save the number again. Only a confirmed number gets customer replies.
  3. Settings: type the Monthly budget for WhatsApp and SMS in the smallest unit of your currency (for euros or dollars, cents: 1000 = 10.00). Each WhatsApp message uses 10 of it (a placeholder, not Meta's price), so 1000 allows about 100 messages. It starts at 0, which blocks WhatsApp. Click Save settings.
  4. For each customer who agreed to WhatsApp messages: open the customer, use Record consent, choose WhatsApp and write how they agreed. Customers without it get no WhatsApp reminders. Their phone number comes from your import.
  5. Before you send your text to Meta for approval: use named variables like {{customer_name}} and {{invoice_number}} (not {{1}}), and end it with "Reply STOP to stop these reminders." The app adds no footer to WhatsApp. (Meta's variable rules: provider, NOT VERIFIED here.)
  6. Settings → Templates, New WhatsApp template:
    • Template key: a short name, for example nudge.
    • Tone and Customer language.
    • Name at Meta and Language code at Meta: exactly as Meta shows them.
    • Text: exactly the text Meta approved.
    Click Add WhatsApp template. It starts as pending. An owner then clicks Meta approved this text; only then is it sent.
  7. Settings → Policies: in the empty "new" row, fill in Days after due, choose whatsapp as Channel, and type your template key as Template. Click Check impact, tick I checked the impact, then click Save policy.

Receipts go by WhatsApp to customers with no email. That needs one more WhatsApp template with the key receipt.

Part 6: Stripe pay links sandbox optional

Stripe lets customers pay by card from a link in the reminder. A Stripe sandbox is a test area where cards are not charged. (provider) Each business connects its own Stripe account inside the app.

Step A: one server key

PAYMENTS_WEBHOOKS=true

Step B: the API key

  1. Sign up at stripe.com. Make or pick a sandbox.
  2. Open the API keys page (dashboard.stripe.com/apikeys).
  3. Stripe suggests a limited key (starts with rk_test_) instead of the secret key (sk_test_). (provider) The app needs it to make, read and turn off payment links, and to read checkout sessions. Which exact permissions are enough was not tested.

Step C: connect, then add the signing secret

  1. In the app: Settings → Integrations, Payments box. Provider Stripe, mode test, paste the API key. Leave Webhook signing secret empty for now. Click Connect.
  2. The app shows the webhook URL once. Copy it. The account stays switched off for now, so no pay link is made yet.
  3. In Stripe, open Workbench → Webhooks and click Create an event destination. Choose Your account and the Snapshot payload. API version: 2026-09-30.endive (the version this app uses).
  4. Select these events: checkout.session.completed, checkout.session.async_payment_succeeded, checkout.session.async_payment_failed, charge.refunded, charge.dispute.created.
  5. Choose Webhook endpoint and paste the webhook URL from step 2.
  6. Click Reveal secret and copy the signing secret (starts with whsec_).
  7. Back in the app, Payments box: choose the Stripe account under Payment account, paste it into Signing secret, click Save signing secret. The account is now switched on.
  • The key must match the mode: a test account needs a test key.
  • A new API key later? Click Connect again with the new key. The webhook URL stays the same.
  • Moving from test to live? Connect again with mode live and a live key. Then, in Stripe's live mode, create the webhook again with the same URL (or click Rotate webhook URL for a new one), and save the live signing secret. Until then the account is switched off.
  • Lost the URL? Click Rotate webhook URL and update it in Stripe.
  • Disconnect switches the account off. To switch it on again, save the signing secret again.
  • Not yet tried with a real Stripe account.

Part 7: alerts, checks and your final list

Alerts (optional)

  • OPS_ALERT_EMAIL: where system problems are emailed. If you set it, also set OPS_ALERT_FROM to a sender your email service has verified. Your technical helper must run the check every 5 minutes (node packages/ops/src/bin/ops.ts watchdog in the services container), and email must be set up. NOT VERIFIED on a hosted server.
  • Slack (per business): make a Slack "incoming webhook" link (it starts with https://hooks.slack.com/). Paste it into Secret under slack (webhook URL). Alerts then go to Slack. Without it, they go to the owners by email.

Never set these on a real server

  • PAYMENTS_ALLOW_FAKE: a fake payment provider, for tests and the demo only.
  • DEMO_MODE, DEMO_NOW, NOW_ISO and the other DEMO_* keys.
  • NEXT_RUNTIME, NEXT_DIST_DIR and OPENAI_LOG.
  • Test-script keys: WEBHOOK_SMOKE, WEBHOOK_URL, WHATSAPP_SMOKE, WHATSAPP_SMOKE_TO, WHATSAPP_SMOKE_TEMPLATE, WHATSAPP_SMOKE_LANGUAGE, WHATSAPP_TOKEN, WHATSAPP_PHONE_NUMBER_ID, STRIPE_SMOKE, STRIPE_TEST_API_KEY, EVAL_LIVE, PROOF_EVAL, PROOF_EVAL_DIR, TENANT_ID, SUPABASE_ANON_KEY, SEND_LOG, APPLY_LOG, MAILPIT_URL.

Leave these alone (they have good defaults or are set for you)

NEXT_OUTPUT, DUELOOP_SERVICE (set by the container image), PORT, HEALTH_MAX_AGE, ALERT_STALE_SECONDS, CLASSIFIER_TIMEOUT_MS, CLASSIFIER_FALLBACKS, PROOF_EXTRACTION_FALLBACKS, SUPABASE_SECRET_KEY and DATABASE_URL (other names for keys you already set), SENTRY_DSN (reserved; does nothing).

Check your setup

In the services container, run the check once for each program: node packages/ops/src/bin/ops.ts doctor --service worker, then with processor and webhooks (on a development machine: pnpm doctor --service web and so on). It checks your settings, the database and Supabase, and that the mail server's port accepts a connection. It does not test your email password. It never shows a key. NOT VERIFIED on a hosted server.
